# Report methodology

## Window and source fields

A report covers an even number of calendar days from 2 to 30. The default is 14 completed days ending yesterday in the chosen IANA time zone (or the system's local zone). The first and second halves have equal length. Explicit end dates are inclusive. Activity dates come from `startTimeLocal`; daily dates come from each requested Garmin calendar date. The time zone chooses the window and does not reassign activity-local dates.

| Measure | Calculation |
| --- | --- |
| Sessions / active days | Count of returned activity summaries / distinct local dates with a summary |
| Exercise time | Sum of activity `duration`, seconds converted to minutes |
| Exercise-load sum | Sum of `activityTrainingLoad`; not Garmin's time-weighted acute load |
| Running distance | Sum of `distance` / 1,000 for `activityType.typeKey == running` |
| Running pace | Total running minutes / total running km; includes recorded duration as supplied |
| Nightly sleep | `sleepTimeSeconds` / 3,600, excluding `napTimeSeconds` |
| Sleep score | `sleepScores.overall.value` |
| Resting HR | Daily-summary `restingHeartRate`, falling back to the heart-rate endpoint only if absent |
| Overnight HRV | `lastNightAvg`; period averages use nightly values, not overlapping `weeklyAvg` values |
| Body Battery | `bodyBatteryAtWakeTime` and `bodyBatteryLowestValue` |
| Stress / steps | Daily-summary `averageStressLevel` / `totalSteps` |

Daily measures are arithmetic means of available values. Summed training measures require complete input. Percentage change is `(second / first - 1) × 100`, undefined when the first period is zero. Session and active-day changes are absolute; recovery changes retain their units, with sleep differences in minutes. Display rounding occurs after aggregation.

## Completeness and missing data

- A short activity page establishes search completion. The report caps activity searches at 20 pages of 99 records and exposes a partial result if the cap is reached.
- An incomplete search or any activity without a local date disables period training totals, daily activity totals, and training comparisons. Retrieved activities remain visible in the log.
- A complete empty activity search means zero recorded sessions. An absent reading, null value, invalid number, or missing resource is unknown, not zero.
- A missing duration or exercise-load value makes its containing sum unavailable. This avoids silently undercounting training. A total over a complete empty activity set is zero.
- Daily averages show sample counts when coverage is incomplete. Comparisons and recovery narrative require full coverage in both periods for the relevant metric.
- Duplicate activity IDs, duplicate calendar dates, mismatching requested/returned dates, and out-of-window activity dates fail generation rather than double-counting or silently filtering records.
- HTTP 204 becomes missing data. API authentication, transport, schema, and rate-limit failures stop a live fetch. A saved bundle with errors displays a coverage notice; raw error strings are not inserted into the report.
- A running record under 100 m over at least 10 minutes is flagged. Its time remains in exercise duration, but its distance and pace are excluded from outdoor comparisons. Treadmill sessions are always separate from outdoor running.

## Interpretation

The summary is generated by fixed rules over the normalized dataset. It changes with the window, measurements, and coverage; it makes no model calls. It reports workload changes and observed recovery readings without assigning a proprietary readiness or health score.

HRV status is shown only when Garmin returns a personal baseline. No baseline means no inferred balanced/unbalanced classification. Garmin explains baseline development and its rolling comparisons in its [HRV guide](https://www.garmin.com/en-US/blog/fitness/understanding-the-hrv-status-on-your-garmin-smartwatch/).

The sleep chart uses a seven-hour reference from [CDC adult sleep guidance](https://www.cdc.gov/sleep/about/). Main-sleep measurements and naps are kept separate. Suggestions prioritize a consistent sleep window when the available main-sleep average is under seven hours.

Running pace comparisons are descriptive: routes, elevation, effort, and duration can differ. Strength and climbing progression require comparable weights, repetitions, or grades beyond these summaries. Garmin's [training status](https://www8.garmin.com/manuals/webhelp/GUID-BD965919-30AA-4EB5-95D7-A899658C50EB/EN-US/GUID-44C7BB4B-EFF7-4A42-AC03-8A6AABB94807.html) includes longer-term inputs beyond summed activity load.

## Saved raw bundle

`--save-json` writes a reusable bundle. `--from-json` reads this format, including older bundles without `schema_version`:

```json
{
  "schema_version": 1,
  "start_date": "2025-03-03",
  "end_date": "2025-03-16",
  "timezone": "America/Los_Angeles",
  "retrieved_at": "2025-03-17T12:00:00+00:00",
  "resources": {
    "activities": [{"requested_date": null, "data": [], "metadata": {"complete": true}}],
    "hrv": [{"requested_date": null, "data": {"hrvSummaries": []}, "metadata": {"complete": true}}],
    "daily": [],
    "sleep": [],
    "heart-rate": []
  },
  "errors": []
}
```

Each daily resource contains entries with `requested_date`, the returned object (or null), and client metadata. The demo generator supplies a complete synthetic example. Inputs are limited to 80 MiB.

The HTML embeds a smaller normalized projection for its controls and downloads. It excludes unused activity identifiers, owner/profile fields, and coordinates. The **Download report data** button exports that projection; it does not export a raw bundle accepted by `--from-json`. CSV exports all retrieved activities regardless of the current table filter. Raw saved bundles retain full responses.

## Rendering

HTML, CSS, JavaScript, and SVG are bundled into one file, without external runtime dependencies. SVG points support pointer and keyboard inspection; tabular daily values are also included. Charts preserve missing-data gaps. HR and HRV axes are cropped and labeled accordingly. The activity log supports text and sport filters. Print mode includes daily readings. Text is escaped for HTML and embedded JSON; CSV cells guard against spreadsheet formula interpretation.
